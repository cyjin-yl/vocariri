# 艺术参考保留与效果适用性

2026-09-25 用户要求：原帧与多帧合成图都是艺术设计参考，在相似艺术花字原型实现前必须保留；参考素材不能直接进入开源发布。每种设计还需要记录结合歌词和画面的适用范围、情感和意味。

## 参考资料的生命周期

存储优先使用现有 `/tank` 工作区，保留已有相对路径；对象存储可作为后续归档位置。原地登记保留索引不等于另做一份备份。若以后迁入对象存储，需要核对具体对象版本、字节数、哈希和实际回读，确认恢复依赖后再另行判断原件是否可清理。

原视频、音频、原尺寸帧、带时间标签的帧、合成图、源时间映射、来源元数据及模型原始回答共同构成研究依据。`cache` 只是现有目录名，不代表可删除。每组资料保持来源、哈希和派生关系；单帧、裁切图、合成图承担不同用途，不能因画面相似就随意去重。

默认保留状态是 `hold_until_prototype_review`。关联的原型必须有可编辑工程或代码、渲染样片、覆盖相关设计关系的复核记录，以及可核对的发布素材来源。只有这些条件满足，相关参考才可标记为清理候选。其他原型、失败记录、复核仍引用它时继续保留；本规则不会自动删除任何文件，也不把“可能重新下载”当作恢复保证。政策登记不是异地备份或全量哈希验证的证明。

第三方参考媒体和花字截图保存在内部研究目录；公开仓库、安装包、示例工程、文档配图和模板预览都要分别检查，不能把图片改名或转换格式后当作原创资产。可公开的是经过检查的总结、原创实现与原创演示；这不会自动授予字体文件、原作插画或第三方工程的再分发许可。示例应使用可再分发或自行制作的字体和图像。版权说明与来源引用可保留，参考媒体不随代码分发。

## 艺术 pattern 需要回答的问题

| 字段 | 记录内容 |
|---|---|
| 原作证据 | 文件、源时间、画面细节、歌词/音频是否实际核对；未知项明确留空 |
| 歌词功能 | 宣言、提问、反复、否定、转折、呼喊、低声独白、叙述、引用等；建议适用项与原作事实分开 |
| 语义关系 | 文字与画面是直接呼应、隐喻、反讽、对抗、补充信息，还是暂不确定 |
| 情感与意味 | 可能传达的情绪、强度、张力与文化联想；记录解释依据、其他可能读法，不当作作者意图或普遍心理规律 |
| 音乐与段落 | 适合短促重音、长音、反复 hook、桥段留白等哪些条件；未听音时只是条件建议，不写成原曲事实 |
| 画面条件 | 主体位置、背景复杂度、遮挡、留白、颜色/明度、运动幅度和阅读时间 |
| 变化方式 | 怎样通过字形、密度、轮廓、节奏和构图改变情感；不能只列颜色或速度滑块 |
| 慎用与反例 | 哪些歌词/画面会被误读、淹没、破坏节奏，或因重复使用显得疲劳 |
| 相邻片段 | 进入前需要的铺垫、退出后的视觉余量、可连续的对象和允许硬切的部分 |
| 原型验证 | 哪些歌词替换、不同脚本、画面密度和输出尺寸用来检验这条建议；审美结论与几何通过分别记录 |

不要求每个 pattern 适合所有歌词；需要留下判断理由。比如有强烈游戏界面联想的像素字，可用于提示、宣告、身份标识或带反讽的赞美；同样的字形也可能让朴素独白显得像游戏播报。这是条件性设计建议，不是禁用清单。

## 给整曲生成与修改使用

外部 Agent 先结合歌词、音乐段落、画面资产和整曲方向选择设计规则，再决定具体动画。选择结果应能解释“这句为什么用它”，同时考虑前后句的密度变化、反复动机和休息段，避免每句都用最强效果。没有核实的原曲情感不得用来硬性标注新项目。

记录允许多种相反解读。例如同一个重复文字墙，可以在明亮有序的编排里显得俏皮，也可以通过密度、遮挡与失序制造逼迫感。Agent 可依据新作品的意图改写或扩展规则，用户仍可手工修改所有参数。模型不必在预设情绪标签中选择，规则也不要求逐效果人工批准。

适用性描述用于检索和创作推理；工程核心仍负责确定性排版、求值和渲染。歌词原文与逐帧渲染不需要反复发送给模型。可复用规则、条件建议、反例和明确的工程差异，有助于减少后续生成时的上下文消耗。

# JIZURA 对照调查

JIZURA 已实现可运行的歌词到文字视频流程，并提供 AE ScriptUI/CEP 接入。Vocariri 的需求范围更广，但当前不能据此声称实现或成片质量领先。应把 JIZURA 纳入功能与渲染对照，优先研究其可复现编排、效果组合和 AE 映射。

调查日期：2026-09-24。源码固定到 [`1b48bea2d74e60f9b0ff2c247aa5919ba03a6551`](https://github.com/852wa/JIZURA/tree/1b48bea2d74e60f9b0ff2c247aa5919ba03a6551)。浏览器实测使用当时的 [公开部署](https://852wa.github.io/JIZURA/)，未证明部署与该提交完全一致。没有启动 AE，也没有把其代码合并进 Vocariri。

| 工作流 | 已查到的 JIZURA 能力 | Vocariri 需求及对照重点 |
|---|---|---|
| 歌词打点 | Space/TAP 标记行首，手动行首时间、LRC；结束时间通常由下一行开始推导 | 每字/罗马字/英文词独立起止、显式休止、方向键跳词与音频寻址；这部分仍须实际实现验收 |
| 自动编排 | 一键选择 mood、风格、效果强度、字体、颜色与种子；保留歌词、时间和锁定行 | 外部 Agent 依据歌词语义、段落与音乐编排整曲，免逐项确认；同时保留不调用模型的手工工作流 |
| 文字与效果 | 布局、入场、保持、退场、装饰、文字处理、背景、镜头、后期、转场分别注册 | 组合思想已经存在，不能将其作为我们独有能力；需要更开放的对象、约束与扩展契约 |
| 重叠和接续 | 当前 cut 加前一 cut 的转场合成；有色差残像、装饰、多元素布局 | 任意多句歌词可各自拥有视觉实例、独立时长和多轨效果；共享镜头/对象状态的连续性不能用转场数量替代 |
| 输出 | MP4；普通/透明 PNG 序列；前景、后景两层透明序列；AE 编排 JSON | 可编辑 AE 工程、明确 Alpha 与色彩契约、素材打包；AE 局部区间缓存渲染后播放 |
| AE | JSX 创建文本/形状图层、内容预合成、cut 包装预合成、镜头 Null；CEP 导入编排与音频、读取标记 | 需要验证浏览器/AE 的视觉差异、失败反馈、局部重渲染及扩展兼容，不能只验证 JSON 可写出 |
| 素材与角色 | 检查的页面导入入口为工程、音频和字体；未发现通用图片/视频素材、分割、头发或骨骼工作流 | 素材、元数据、遮罩、分层、曲线、网格、骨骼等可组合结果供 Agent 操作；结论仅限本次检查范围 |
| 扩展 | 公开 JS 效果注册 API 与 contributor guide；扩展包提供 plan/render/apply 钩子 | 不能说对方被固定预设封死。我们的外部 Agent/CLI、工程版本、可任意修改模块和确定性求值仍需完整落地 |

打点实现见 [`src/12_ui.js`](https://github.com/852wa/JIZURA/blob/1b48bea2d74e60f9b0ff2c247aa5919ba03a6551/src/12_ui.js) 的 `tapNow`，时序见 [`src/08_planner.js`](https://github.com/852wa/JIZURA/blob/1b48bea2d74e60f9b0ff2c247aa5919ba03a6551/src/08_planner.js) 的 `computeTiming`。不能把每字符入场错峰动画当作每字音频标注。

[`src/08b_omakase.js`](https://github.com/852wa/JIZURA/blob/1b48bea2d74e60f9b0ff2c247aa5919ba03a6551/src/08b_omakase.js) 的 mood 选择由随机函数和标签驱动；本次未发现歌词情感语义模型。音频分析有能量包络、起音与 BPM 网格，这与理解歌词含义是两种能力。

[`src/09_render.js`](https://github.com/852wa/JIZURA/blob/1b48bea2d74e60f9b0ff2c247aa5919ba03a6551/src/09_render.js) 的 `cutAt` 返回一个 cut；转场会额外合成前一个 cut 的接近结束帧。测试两个重叠区间，在交叠时刻只选中后一个。这个架构支持转场与布局中的多个元素，但不是任意并行的歌词轨道。是否有其它特殊布局模拟叠句，未穷尽测试。

AE 的 [`ae/05_reg.jsx`](https://github.com/852wa/JIZURA/blob/1b48bea2d74e60f9b0ff2c247aa5919ba03a6551/ae/05_reg.jsx) 优先使用原效果实现，缺失时才使用映射或默认值，并记录 fallback；CEP 返回替代数量、日志和缺失字体。不能因导出文件里存在旧映射表就断言所有新增效果都会退化，也不能声称两端完全一致。实际 AE 成片比较仍待做。

实测注册数：布局 140、入场 100、保持 38、退场 86、装饰 115、文字处理 52、背景 62、镜头 28、后期 66、转场 20，合计 707。它们是注册条目，含无效果项；不是 707 个已验收完整模板，更不是 707 个独立 PV 观察形式。没有将它们加入我们的 3000–5000 形式研究完成数。

浏览器使用独立无登录 Edge 会话和两行自写英文测试文本。相同项目和种子的两次 plan 序列化一致。320×180、12 fps、0.5 秒无音频小样成功生成 H.264 High MP4（27,532 字节）、6 张透明 PNG（ZIP 52,481 字节）和 12 张前后景 PNG（ZIP 97,851 字节）；两份 ZIP CRC 均通过。一个透明渲染帧包含全透明、部分透明和不透明像素。AE JSON 为 version 2，含 2 个 cuts。此测试没有验证长曲、4K、音画同步、全部效果 Alpha 正确性或前后景合成逐像素一致。

本地证据在 `research/cache/jizura/`：固定源码快照、检索记录、哈希清单、UI 截图、浏览器探针输出与实际导出。首次页面下载、Git clone 和若干 raw 请求失败均保留；API blob 回退取得主要审查文件。`index.html` 首次副本不完整，不能当完整源码。缓存已被 Git 忽略。

许可证为 MIT，版权标注 `Copyright (c) 2026 hakoniwa`；复用实质代码时须保留许可与版权。第三方清单另列 mp4-muxer MIT 与运行时字体 OFL。当前只做调查，未复用代码、再分发字体或发布媒体。

后续对照应使用同一份歌词、时间戳、音频、画幅和字体，分别测完整歌曲的节奏安排、可读性、重叠、休止、转场、渲染成本及 AE 往返差异。先选具有代表性的效果小样，不用随机种子或参数组合扩充研究数量。远端 Luna 已收到公开项目链接，按工具机制参考归档；PV 来源调查继续覆盖更广作者和形式。
